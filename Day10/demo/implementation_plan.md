# note-demo 구현 계획

- 상태: v1.0 승인 — 코드 생성·로컬 테스트 완료, 공개 배포 미실행
- 작성일: 2026-10-27
- 기준 문서: [ai_agent_prompt.md](ai_agent_prompt.md), [prompt.md](prompt.md)
- 사용자 승인에 따라 애플리케이션 코드 생성과 로컬 검증을 수행했다. 실제 실행·배포 명령은 README.md를 기준으로 한다.
- 배포 대상은 PythonAnywhere 무료 계정의 일반 WSGI 웹 앱이다. 실제 계정 배포는 아직 수행하지 않았다.

## 1. 구현 목표와 범위

회원 기능과 게시판을 제공하고 로컬과 PythonAnywhere 무료 계정에서 실행할 수 있는 데모를 만든다. 게시글 제목 목록은 페이지당 10개이며, 상세 조회·본인 글 수정 및 삭제·댓글 작성 및 조회를 제공한다. 제목·본문·댓글의 불쾌한 표현을 마스킹하고 관리자가 표현 사전을 추가·삭제한다.

비밀번호 찾기는 안내만 제공하는 목업이다. SNS 로그인, 실제 메일 발송, 운영용 인증 체계, 회원 탈퇴, 댓글 수정·삭제, 첨부파일, 검색, 좋아요는 이번 범위에서 제외한다.

## 2. 무료 배포에 맞춘 기술 구성

사용자가 지정한 PythonAnywhere 무료 배포를 기준으로 아래 구성을 채택한다. 무료 계정의 생성 시기에 따른 추가 기능에 의존하지 않는다.

| 영역 | 제안 | 선택 이유 |
| --- | --- | --- |
| 백엔드 | Python + Flask, 일반 WSGI | PythonAnywhere Web 탭의 기본 배포 절차 사용 |
| 화면 | HTML + CSS + 기본 JavaScript | 작은 화면 수에 맞춰 별도 프런트엔드 빌드 과정 생략 |
| 데이터베이스 | SQLite + Python sqlite3 | 별도 DB 서버 없이 파일로 데이터를 유지 |
| 인증 | Flask 서명 쿠키 + DB의 session_version | 메모리 세션을 제거하고 리로드 전후에도 동일한 검증 유지 |
| 비밀번호 저장 | Werkzeug 해시 검증 함수 | Flask 의존성을 활용하여 별도 인증 서버 없이 평문 저장 방지 |
| 마스킹 | 키워드 방식, 영문 대소문자 무시 | 관리 화면과 동작을 단순하게 유지 |
| 검증 | 로컬 pytest + Flask 테스트 클라이언트, 배포 후 브라우저 확인 | 무료 서버에서는 무거운 테스트 실행을 필수로 하지 않음 |

서버가 화면과 API를 같은 출처에서 제공한다. PythonAnywhere Web 앱과 가상환경의 Python 버전을 일치시킨다. 배포용 `requirements.txt`에는 Flask와 필요한 실행 의존성만 고정하고, pytest 등은 `requirements-dev.txt`로 분리한다. 실제 버전과 설치 가능 여부는 구현 단계에서 확인한다.

**제거·변경한 설계**

- FastAPI·Uvicorn 실행과 ASGI 배포 절차를 제거하고 Flask WSGI 진입점으로 교체한다. ASGI 지원 자체가 없다는 뜻은 아니며, 실험 배포 기능에 의존하지 않는 선택이다.
- 서버 메모리의 세션 저장소를 제거한다. 재시작으로 로그인 여부가 바뀌는 정책도 함께 변경한다.
- 외부 DB, Redis, Docker, Node 빌드 서버, WebSocket, 별도 백그라운드 프로세스, 예약 작업을 배포 필수 구성으로 추가하지 않는다.
- 앱 실행 중 인터넷에서 표현 사전을 수집하지 않는다. 개발 환경에서 조사한 seed를 업로드하고 이후 관리자 화면에서 관리한다.
- 무료 환경의 경량 데모로 범위를 한정한다. SQLite로 대규모 동시 쓰기 처리나 상용 운영 성능을 보장하지 않는다.

**무료 계정 조건과 설계 반영**

2026-10-27 확인 기준 공식 안내는 웹 앱 1개·웹 워커 1개·512 MiB 저장 공간·1개월 만료를 명시한다. CPU·콘솔 사용에도 한도가 있다. 계정별 최신 수치는 배포 시 대시보드에서 다시 확인한다. 새 무료 계정은 MySQL과 일일 예약 작업을 기본 제공한다고 가정하지 않는다. 외부 인터넷 접근은 허용 목록의 제한을 받으므로 실행 중 외부 API 호출에 의존하지 않는다. 무료 기본 도메인을 사용하고 Web 탭에서 만료일·연장 절차를 확인한다.

공식 근거: [Flask 배포](https://help.pythonanywhere.com/pages/Flask/), [ASGI 실험 배포](https://help.pythonanywhere.com/pages/ASGICommandLine), [무료 계정 조건](https://help.pythonanywhere.com/pages/FreeAccountsFeatures/), [데이터베이스 지원](https://help.pythonanywhere.com/pages/KindsOfDatabases), [무료 외부 접근 허용 목록](https://www.pythonanywhere.com/whitelist/). 초기 표현 사전 출처 조사는 별도 수행한다.

## 3. 간단한 화면 구성

공통 헤더와 한 개의 본문 영역을 사용한다. 기본 배경, 읽기 쉬운 글자, 명확한 버튼과 입력창으로 구성한다. 로그인 화면에 큰 소개 영역이나 별도 대시보드를 추가하지 않는다.

| 화면/경로 제안 | 표시 내용 | 주요 동작 |
| --- | --- | --- |
| 게시글 목록 `/` | 제목과 본인 글의 `내 글` 배지, 페이지 이동 | 상세 이동, 글쓰기 |
| 회원가입 `/signup` | 이메일·닉네임·비밀번호 | 가입 후 로그인 이동 |
| 로그인 `/login` | 이메일·비밀번호 | 로그인, 가입·비밀번호 찾기 이동 |
| 비밀번호 찾기 `/forgot-password` | 이메일, 목업 안내 | 입력 검사 후 미발송 안내 |
| 게시글 상세 `/posts/{id}` | 제목·본문, 댓글, 목록 버튼 | 본인 글 수정·삭제, 댓글 등록 |
| 작성 `/posts/new`, 수정 `/posts/{id}/edit` | 공통 제목·내용 폼 | 저장, 취소 |
| 표현 관리 `/admin/mask-rules` | 표현 목록·추가 입력·삭제 버튼 | 관리자만 규칙 변경 |

- 공통 헤더: `note-demo`, 비로그인 시 로그인·회원가입, 로그인 시 닉네임·로그아웃, 관리자에게만 표현 관리 링크.
- 비로그인 사용자는 공개 글과 댓글을 읽을 수 있다. 작성 버튼 또는 작성 동작에서 로그인을 안내한다.
- 게시글 목록에 작성자·날짜·본문 미리보기를 추가하지 않는다.
- 오류는 필드 가까이에, 성공 안내는 짧게 표시한다. 댓글 전송 실패 시 입력값을 유지한다.
- 본문과 댓글의 줄바꿈은 유지하고 HTML로 해석하지 않는다. 삭제는 간단한 확인창을 사용한다.
- 작은 화면에서도 가로 스크롤 없이 주요 입력과 버튼을 사용할 수 있게 한다.

## 4. 데이터베이스 구현 계획

ERD와 컬럼 정의의 기준은 `ai_agent_prompt.md` 5.2~5.4절이다. 중복 정의로 불일치를 만들지 않도록 실제 스키마와 문서의 대응을 확인한다.

| 테이블 | 구현 내용 |
| --- | --- |
| users | 회원 ID, 정규화한 고유 이메일, 닉네임, password_hash, USER/ADMIN 역할, session_version, 가입 시각 |
| posts | 게시글 ID, 작성자 FK, 제목·본문 원문, 생성·수정 시각 |
| comments | 댓글 ID, 게시글 FK, 작성자 FK, 내용 원문, 생성 시각 |
| mask_rules | 규칙 ID, KEYWORD 유형, 정규화한 고유 표현, 생성 시각 |

- SQLite에서는 PK를 `INTEGER PRIMARY KEY`로 구현한다. 인증 검증 컬럼은 `password_hash`로 구체화한다. `session_version`은 NOT NULL INTEGER, 기본값 0, 0 이상 CHECK로 추가한다.
- 날짜는 UTC ISO 8601 형식의 동일한 정밀도로 저장한다. 화면 표시가 필요한 경우 사용자 시간대로 변환한다.
- 모든 DB 연결에서 `PRAGMA foreign_keys = ON`을 적용한다.
- 회원 FK 삭제는 RESTRICT, 게시글 삭제에 따른 댓글 삭제는 CASCADE로 구현한다.
- NOT NULL, 이메일 UNIQUE, 규칙 복합 UNIQUE, 역할·규칙 유형 CHECK와 길이·공백 검사를 적용한다. SQLite의 VARCHAR 선언만으로 길이 제한이 적용된다고 가정하지 않는다.
- 게시글 정렬 `(created_at, id)`, 댓글 조회 `(post_id, created_at, id)`, 작성자 FK 인덱스를 만든다.
- SQL 입력은 매개변수로 전달한다. 쓰기 작업과 연관 삭제는 트랜잭션 단위로 처리한다.
- DB는 공개 정적 파일 경로 밖에 두고 `DATABASE_PATH`의 절대 경로로 지정한다. PythonAnywhere 예시는 `/home/<username>/note-demo/data/note_demo.db`다. DB 파일과 상위 디렉터리에 쓰기 권한이 있어야 한다. 초기화는 명시적 명령으로만 수행하며 WSGI import·Reload 때 스키마 재생성이나 seed 재주입을 하지 않는다.
- 기본 rollback journal을 사용하고 WAL은 자동 활성화하지 않는다. 요청 단위 연결, 짧은 트랜잭션, 제한된 busy timeout으로 잠금 대기를 처리한다. 잠금 실패 시 재시도 가능한 안내를 제공한다.
- 로컬 데모 seed는 일반 사용자 2명과 관리자 1명, 예제 글 21개와 일부 댓글을 제공한다. 공개 배포의 관리자 비밀번호는 초기화 시 별도 입력하고, 문서에 공개된 공통 관리자 비밀번호를 사용하지 않는다. seed 재실행으로 삭제된 규칙이 되살아나지 않도록 한다.
- 테스트는 별도 임시 DB를 사용한다. 애플리케이션 데이터는 기본 4개 테이블로 유지한다.

## 5. 인증·권한과 API 계획

로그인 시 서버가 비밀번호를 검증하고 Flask 서명 쿠키 세션을 발급한다. 쿠키에는 사용자 ID, 로그인 시의 session_version, 발급 시각, CSRF 토큰만 담는다. 서명 쿠키는 암호화 저장소가 아니므로 비밀번호·해시·관리자 역할을 담지 않는다. 권한은 매 요청 DB의 현재 회원 정보로 판단한다. 쿠키는 HttpOnly·SameSite=Lax를 사용하고 공개 배포에서는 Secure를 적용한다. 가입·로그인·로그아웃을 포함한 상태 변경 요청에 CSRF 검증을 적용한다.

세션은 로그인 후 최대 8시간으로 제한하고 활동에 따라 무한 연장하지 않는다. 새로고침·WSGI Reload에도 DB와 SECRET_KEY가 같으면 만료 전 로그인을 유지한다. 로그아웃은 DB의 session_version을 원자적으로 증가시키고 쿠키를 지운다. 이후 이전 쿠키는 재사용할 수 없다. 단순화를 위해 해당 계정의 다른 기기도 함께 로그아웃되는 정책을 안내한다. 만료, 없는 사용자, 버전 불일치는 인증 실패로 처리한다. 이는 데모 인증 범위이며 실제 재설정·SNS 로그인·운영용 인증 체계는 포함하지 않는다.

SECRET_KEY는 최초 배포 시 생성하여 프로젝트·정적 경로 외부의 비공개 설정에 보관하고 WSGI에서 읽는다. Reload 때마다 재생성하지 않는다. 실제 키와 관리자 초기 비밀번호는 소스·로그·배포 압축 파일에 포함하지 않는다.

| API 제안 | 권한과 처리 |
| --- | --- |
| `POST /api/auth/signup` | 공개; 회원가입, 역할은 USER로 고정 |
| `POST /api/auth/login` | 공개; 데모 인증 후 세션 발급 |
| `POST /api/auth/logout` | session_version 증가로 해당 계정의 기존 세션 무효화, 쿠키 제거 |
| `GET /api/auth/me` | 현재 사용자·역할·요청용 CSRF 토큰 확인; 비밀번호 제외 |
| `POST /api/auth/forgot-password` | 공개; 이메일 형식 검사와 목업 안내만 반환 |
| `GET /api/posts?page=1` | 공개; 제목·이동용 ID, 페이지 정보 반환; 페이지당 10개 |
| `POST /api/posts` | 로그인 필요; 작성자를 세션에서 결정 |
| `GET /api/posts/{id}` | 공개; 마스킹한 상세 반환 |
| `GET /api/posts/{id}/edit` | 작성자 본인만; 편집용 원문 반환 |
| `PATCH /api/posts/{id}` | 작성자 본인만 수정 |
| `DELETE /api/posts/{id}` | 작성자 본인만 삭제 |
| `GET /api/posts/{id}/comments` | 공개; 해당 글의 마스킹한 댓글 반환 |
| `POST /api/posts/{id}/comments` | 로그인 필요; 댓글 작성 |
| `GET /api/admin/mask-rules` | 관리자만 표현 목록 조회 |
| `POST /api/admin/mask-rules` | 관리자만 표현 추가 |
| `DELETE /api/admin/mask-rules/{id}` | 관리자만 표현 삭제 |

API 경로는 구현 편의에 따라 조정할 수 있으나 권한과 동작은 유지한다. 인증 실패 401, 권한 부족 403, 없는 리소스 404, 중복 409, 입력 오류 422를 일관되게 처리한다. 잘못된 페이지는 유효 범위로 보정한다. 게시글·댓글·역할 변경 요청에서 클라이언트가 보낸 작성자나 관리자 정보를 신뢰하지 않는다.

## 6. 마스킹과 초기 사전

1. 배포 전 개발 환경에서 공개 자료를 조사하여 한국어 중심 초기 사전을 구성한다. 출처 URL·확인일·재사용 조건·선정 기준을 `docs/masking_sources.md`에 기록한다. 실행 서버에서 검색·크롤링하지 않는다.
2. 키워드는 앞뒤 공백을 제거하고 영문을 소문자로 정규화해 중복을 차단한다. 정규식 유형 입력은 거부한다.
3. 키워드를 정규식 내부에서 사용할 경우 반드시 리터럴 이스케이프한다. 사용자에게 정규식 편집 기능은 제공하지 않는다.
4. 원문에서 모든 키워드의 일치 구간을 찾고, 겹치는 구간을 합친 뒤 각 문자를 `*`로 바꾼다. 규칙 등록 순서와 관계없이 동일한 결과를 만든다.
5. 영문 대소문자는 무시한다. 공백·기호 삽입, 초성 변환 등 우회 표현의 자동 정규화는 이번 기본 범위에 넣지 않는다. 필요한 변형은 별도 키워드로 등록할 수 있다.
6. 제목·본문·댓글 표시 API에서 현재 규칙을 적용한다. 비작성자에게 원문을 함께 반환하지 않는다. 작성자 편집 API만 원문을 제공한다.
7. 초기 구현에서는 요청 시 현재 사전을 읽어 적용한다. 관리자 변경 후 화면을 다시 조회하면 기존 데이터에도 즉시 반영된다.
8. 규칙 삭제 시 기존 글의 원문 표현이 다시 보일 수 있음을 관리 화면에서 안내한다.
9. 네트워크나 이용 조건 때문에 최신 초기 사전을 구성하지 못하면 데모 규칙만 제공하고 R08을 미완료로 남긴다. 사용자에게 제약을 알린 뒤 후속 조치에 대한 피드백을 받는다.

## 10. PythonAnywhere 배포 절차

계정명·실제 홈 경로·지원 Python 버전은 배포 시 확인한다. 아래 `<username>` 등은 치환할 값이며 임의 계정으로 확정하지 않는다. 계정 접근이 없는 상태에서는 실제 배포 성공으로 보고하지 않는다.

1. **업로드:** Files 화면의 업로드 또는 계정에서 가능한 Git 경로로 프로젝트를 `/home/<username>/note-demo`에 배치한다. 로컬 가상환경·테스트 캐시·실제 비밀값은 업로드하지 않는다. DB는 최초 생성하며 이후 코드 업데이트 때 덮어쓰지 않는다.
2. **가상환경:** Bash 콘솔에서 Web 탭과 일치하는 지원 Python으로 가상환경을 만들고 `pip install -r requirements.txt`를 실행한다. pytest와 브라우저 도구는 배포 필수 패키지에서 제외한다.
3. **비공개 설정:** 홈 아래 별도 비공개 설정 파일에 고정 SECRET_KEY, DATABASE_PATH, 배포 모드, 허용 호스트를 설정한다. 파일 경로는 WSGI에서 명시하고 Bash 환경 변수가 웹 프로세스에 자동 전달된다고 가정하지 않는다. 설정 누락 시 기본 비밀키로 실행하지 않는다.
4. **DB 생성:** `python scripts/init_db.py`로 테이블·초기 사전을 생성하고 관리자 비밀번호를 별도로 입력한다. 공개 배포에 로컬 데모 관리자 비밀번호가 남지 않는지 확인한다.
5. **Web 앱:** Web → Add a new web app → Manual configuration에서 가상환경과 같은 Python 버전을 선택한다. Web 탭의 Source code·Working directory·Virtualenv 경로를 실제 위치로 설정한다.
6. **WSGI 연결:** PythonAnywhere가 제공한 WSGI 설정 파일에서 프로젝트 경로를 `sys.path`에 추가하고 비공개 설정 경로를 지정한 뒤 `from wsgi import application`으로 앱을 불러온다. 프로젝트 `wsgi.py`는 `create_app()`의 반환값을 `application`으로 노출한다.
7. **정적 파일:** Web 탭에서 `/static/`을 `/home/<username>/note-demo/app/static/`에 연결한다. DB·설정·프로젝트 전체 폴더는 정적 매핑하지 않는다.
8. **Reload·확인:** debug를 끄고 HTTPS·Secure 쿠키 설정을 확인한 뒤 Reload한다. 공개 URL에서 목록·정적 파일·가입·로그인·본인 글 권한·댓글·마스킹·관리자 접근을 점검한다. Reload 후 데이터와 만료 전 로그인이 유지되는지 확인한다.
9. **장애 확인:** 오류 시 Web 탭의 error/server 로그에서 import·가상환경 버전·설정 파일·DB 경로와 쓰기 권한을 확인한다. 콘솔에서 `app.run()`이나 Uvicorn을 계속 실행해 공개 서비스를 유지하지 않는다.
10. **유지 관리:** 코드 갱신 전 `sqlite3` backup API로 수동 백업하고 DB·SECRET_KEY를 보존한다. 복구는 쓰기 요청을 중단한 상태에서 수행한다. 예약 작업 없는 계정에서도 가능한 수동 절차로 문서화한다. 만료일과 저장 공간은 대시보드에서 확인하고 필요 시 연장한다.

WSGI 모듈을 불러오는 것만으로 서버 실행, DB 초기화, 관리자 생성, 외부 수집이 일어나지 않아야 한다. 로컬 실행 명령과 PythonAnywhere 배포 절차는 README에서 구분한다.

## 11. 피드백 반영과 변경 이력

사용자의 PythonAnywhere 무료 배포 조건을 반영하여 기술 스택·세션·패키지 구성·초기 사전 조사 위치·배포 검증을 수정했다. 화면은 간단한 목록·폼 구성, 마스킹은 키워드 방식으로 유지한다. 이후 v1.0 승인에 따라 코드를 생성하고 자동 테스트와 실제 브라우저 검증을 수행했다. 공개 배포는 미실행이다.
