# 2차시. 답변 번호와 개선 이유를 연결해 피드백 받기

## 1. 학습목표

[오늘 수업 안내](../TODAY_GUIDE.md)를 읽습니다. 여행 프로필이 적용된 챗봇에서 어떤 답변이 왜 도움이 되지 않았는지 구분합니다. 이전의 속도 평가와 달리, 이번에는 **답변 번호와 개선 원인**을 연결합니다.

- 서로 다른 두 답변의 평가가 섞이지 않는지 확인할 수 있습니다.
- ‘개선 필요’를 선택했을 때만 이유를 필수로 요구하도록 바꿀 수 있습니다.
- 같은 답변을 재평가하면 기존 평가를 바꾸는 정책을 설명할 수 있습니다.

## 2. 중요 알고리즘 및 코드를 읽을 때 반드시 알아야 할 내용

여행 일정을 두 번 물었는데 ‘개선 필요’라는 평가 하나만 남았습니다. 어느 답변이 문제였는지 모르면 고칠 부분을 찾기 어렵습니다. 답변마다 고유한 번호를 붙이면 평가가 가리키는 대상을 분명히 할 수 있습니다.

정상 완료한 답변에 `message_id`를 한 번 부여합니다. `uuid4()`는 겹칠 가능성이 매우 낮은 식별자를 만들며, 실제 값은 실행마다 다릅니다. 새로 화면을 그릴 때 번호를 다시 만들지 않습니다. 답변 번호는 사람이 로그인한 계정을 뜻하지 않습니다.

```python
st.session_state.feedback[message_id] = record
```

`feedback`은 답변 번호를 키로 쓰는 딕셔너리입니다. 같은 번호에 다시 저장하면 평가를 바꿉니다. 다른 번호이면 다른 평가가 됩니다. 예를 들어 `답변 A: 개선 필요`, `답변 B: 미평가`를 따로 구분합니다.

`requires_reason(rating)`은 점수를 받아 이유가 필요한지 판단합니다. 이 앱에서는 ‘도움이 됨’을 1, ‘개선 필요’를 0으로 바꿉니다. `0`도 유효한 평가이므로 평가 없음과 혼동하지 않습니다. 평가 폼 안의 자유 메모는 현재 화면에서만 참고하며 평가 기록에는 넣지 않습니다.

참고: [Streamlit 폼](https://docs.streamlit.io/develop/concepts/architecture/forms), [단일 선택 입력](https://docs.streamlit.io/develop/api-reference/widgets/st.radio).

## 3. 코드 제공

실행 파일은 [main.py](main.py)입니다. Windows CMD에서 실행합니다. `.env`가 이미 있으면 복사 명령을 생략합니다.

```bat
cd /d C:\AI4\KDT_Personal_Travel\lesson02
python -m pip install -r requirements.txt
copy .env.example .env
notepad .env
python -m streamlit run main.py
```

`GROQ_API_KEY`에 본인 키를 입력합니다. Local URL을 열고, 종료할 때 CMD에서 Ctrl+C를 누릅니다. 현재 평가는 이 브라우저 연결의 임시 기록이며 DB에는 전송하지 않습니다.

### 1단계. 두 답변 중 하나만 평가

프로필을 적용한 뒤 다음 두 질문을 차례로 보냅니다.

> 경주에서 도보 중심으로 둘러볼 반나절 코스를 알려 주세요.

> 비가 오면 바꿀 수 있는 실내 대안을 제안해 주세요.

첫 답변 아래에서 ‘개선 필요’를 선택하고 이유는 ‘선택 없음’인 채 **피드백 저장**을 누릅니다. 현재 `requires_reason()`의 `return False` 때문에 이유 없이도 `피드백 저장 완료`가 보입니다. 둘째 답변에는 저장 완료 표시가 없는지 확인합니다.

### 2단계. 부정 평가의 이유만 필수로 바꾸기

`requires_reason()` 함수만 교체합니다.

```python
def requires_reason(rating):
    return rating == 0
```

`==`는 두 값이 같은지 비교합니다. `rating`이 0이면 `True`, 1이면 `False`이므로 개선이 필요한 답변에만 이유를 요구합니다. 모든 평가에 긴 글을 강요하는 대신 필요한 원인만 선택하게 합니다.

### 3단계. 저장 거절과 재평가 확인

첫 답변의 ‘개선 필요’와 ‘선택 없음’을 유지하고 다시 저장합니다. `개선 이유를 선택하세요.`가 보이면 ‘조건 미반영’을 선택해 다시 저장합니다. 이어 같은 답변을 ‘도움이 됨’으로 바꿔 저장합니다. 답변 ID가 그대로인지 확인합니다. 저장 완료 아래의 **저장된 평가**와 **저장된 이유**를 봅니다. 폼의 선택값만 바꿨을 때에는 이 저장값이 그대로이고, 저장 버튼을 눌러야 바뀝니다.

새 답변에 평가를 붙인 것과 기존 답변을 다시 평가한 것은 다릅니다. 이번 앱은 한 답변의 최신 평가 하나를 유지합니다. 모든 클릭 이력을 별도 사건으로 누적하는 정책과 구분합니다.

### 예상 결과

| 입력·조작 | 결과 |
| --- | --- |
| 수정 전, 개선 필요 + 선택 없음 | 저장 완료 |
| 수정 후, 개선 필요 + 선택 없음 | `개선 이유를 선택하세요.` |
| 수정 후, 개선 필요 + 조건 미반영 | 첫 답변에 저장 완료 표시 |
| 둘째 답변을 저장하지 않음 | 둘째 답변에 저장 완료 표시 없음 |
| 첫 답변을 다시 평가 | 첫 답변 ID 유지, 저장된 평가 1로 교체 |

AI 답변의 문장은 고정되지 않습니다. 평가 대상은 실제로 화면에 나온 해당 답변입니다. 합성 질문으로 동작을 확인하고 이름·연락처·예약번호는 메모에 입력하지 않습니다.

## 4. 복습 과제

`show_feedback()`의 개선 이유 선택 목록에 ‘이동 시간이 과함’을 추가합니다. 두 답변 중 하나에 새 이유를 골라 저장하고, 다른 답변의 저장 표시가 바뀌지 않는지 확인합니다.

‘도움이 됨’에는 이유가 없어도 저장되고 ‘개선 필요’에는 이유가 있어야 저장되는 입력 조합을 각각 한 번 실행합니다. 두 경우의 화면 문구를 기록합니다. 다음 차시는 별도 완성 파일로 시작합니다.
