# 1차시. 여행 프로필을 확정하고 답변에 적용하기

## 1. 학습목표

[오늘 수업 안내](../TODAY_GUIDE.md)를 먼저 읽습니다. Day20의 여행 챗봇은 스트리밍과 성공한 대화 이력을 그대로 사용합니다. 오늘은 질문마다 여행 조건을 반복해서 쓰는 불편을 줄이고, 화면에서 확정한 조건을 답변에 적용합니다.

- 여행 스타일·이동 수단·답변 형식을 선택하고 적용할 수 있습니다.
- 선택 중인 값과 적용된 프로필을 구분할 수 있습니다.
- 여유로운 여행의 방문 장소 수를 한 함수에서 바꿔 비교할 수 있습니다.

| 차시 | 새로 해결할 문제 | 확인할 결과 |
| --- | --- | --- |
| 1 | 반복해서 입력하는 여행 조건 | 적용된 여행 프로필 |

| 6 | 공개 서비스의 입력·호출 폭주 | 길이·연속 호출 제한 안내 |

## 2. 중요 알고리즘 및 코드를 읽을 때 반드시 알아야 할 내용

‘대중교통을 이용하고 천천히 둘러보고 싶다’는 조건을 매 질문마다 다시 쓰면 번거롭습니다. 반대로 선택창의 값을 바꾸기만 했는데 기존 대화의 조건이 조용히 바뀌면 어느 조건으로 답했는지 헷갈립니다.

**프로필 폼**에서 선택한 값은 적용 버튼을 눌렀을 때 확정합니다. 모델에 주는 `instructions`는 확정된 프로필을 읽습니다. 작성 중인 선택값과 적용한 값을 구분하면, 조건 변경 시점을 화면과 코드에서 함께 확인할 수 있습니다.

대화가 있는 상태에서 프로필 값을 바꾸려면 초기화 동의가 필요합니다. 확인한 뒤 변경을 적용하면 이전 조건의 대화를 비웁니다. 같은 프로필을 그대로 다시 적용하면 대화는 유지합니다. 단순히 새 대화를 시작할 때에는 적용한 프로필을 유지합니다. 프로필과 대화는 현재 Streamlit 연결의 임시 메모리에 있으므로 새 브라우저 연결이나 서버 재시작 뒤의 복원은 보장하지 않습니다.

`itinerary_rule(profile)`은 프로필을 읽어 여행 장소 수에 관한 문장 하나를 돌려줍니다. `profile["style"]`은 프로필 딕셔너리에서 `style`이라는 이름으로 저장한 값을 꺼내는 표현입니다. 모델은 이 문장을 지침으로 받으며, 화면에는 선택한 프로필이 표시됩니다.

참고: [Streamlit 폼](https://docs.streamlit.io/develop/concepts/architecture/forms), [Groq Responses API](https://console.groq.com/docs/responses-api).

## 3. 코드 제공

실행 파일은 [main.py](main.py)입니다. Windows CMD에서 해당 폴더로 이동해 실행합니다. 기존 Python 실습 환경을 사용합니다. `.env`가 이미 있으면 `copy`를 생략해 키를 덮어쓰지 않습니다.

```bat
cd /d C:\AI4\KDT_Personal_Travel\lesson01
python -m pip install -r requirements.txt
copy .env.example .env
notepad .env
python -m streamlit run main.py
```

`.env`의 `GROQ_API_KEY`를 본인 값으로 바꾸고 저장합니다. 표시된 Local URL을 브라우저에서 엽니다. Groq 호출은 이 앱의 서버가 수행하므로 별도 FastAPI·Redis 서버는 필요 없습니다. 종료는 CMD에서 Ctrl+C입니다.

### 1단계. 선택 중인 값과 적용한 값 비교

프로필을 여유로운 여행·대중교통으로 선택해 적용합니다. 다음 질문을 보냅니다.

> 부산역에서 출발해 반나절 동안 여행하려고 합니다. 이동 순서와 쉬는 시간을 제안해 주세요.

다른 이동 수단을 선택하기만 한 뒤 현재 적용된 프로필을 봅니다. 적용 전에는 이전 조건이 유지되어야 합니다. 초기화 동의 없이 **프로필 적용**을 눌러 `프로필을 바꾸려면 대화 초기화에 동의하세요.`를 확인합니다. **프로필 변경 시 현재 대화 초기화에 동의**를 체크한 뒤 적용하면 이전 대화가 비워지는지 확인합니다. 새 대화 버튼으로만 초기화할 때에는 프로필이 유지되는지 비교합니다.

현재 `itinerary_rule(profile)`의 시작 줄은 `return "하루 방문지는 4곳 이내로 제안한다."`입니다. 기본 방문 장소 수를 4곳으로 안내합니다. 여행 스타일이 여유롭더라도 장소 수를 같은 기준으로 제안하는 시작 정책입니다.

### 2단계. 장소 수를 정하는 함수 한 곳 바꾸기

`main.py`의 `itinerary_rule()` 함수만 아래 함수로 교체합니다.

```python
def itinerary_rule(profile):
    if profile["style"] == "여유롭게":
        return "하루 방문지는 2곳 이내로 정하고 장소 사이에 휴식 시간을 넣는다."
    return "하루 방문지는 4곳 이내로 제안한다."
```

`if`의 조건이 맞으면 바로 아래 들여쓴 문장을 실행합니다. `return`은 문장을 돌려주고 함수를 끝내므로, ‘여유롭게’이면 2곳과 휴식을 안내하고 다른 스타일이면 마지막 4곳 지침을 사용합니다. 사용자가 입력한 기간에 맞게 일정을 조정하는 여행 지침과 함께 전달됩니다.

### 3단계. 같은 질문으로 비교

파일을 저장하고 새 대화를 시작합니다. 여유로운 스타일을 적용한 상태에서 같은 질문을 보냅니다. 다른 스타일에서도 같은 질문을 보내 장소 수 기준이 구분되는지 확인합니다. AI 문장 자체보다 적용 프로필과 장소 수 지침의 차이를 먼저 봅니다.

### 예상 결과

| 조작 | 고정해서 확인할 결과 |
| --- | --- |
| 폼에서 선택만 변경 | 적용 프로필은 이전 값 유지 |
| 변경한 프로필, 초기화 동의 없이 적용 | 경고, 기존 프로필과 대화 유지 |
| 초기화 동의 후 변경 적용 | 새 프로필 표시, 이전 대화 초기화 |
| 같은 프로필 그대로 적용 | 기존 대화 유지 |
| 새 대화만 시작 | 대화는 비워지고 적용 프로필 유지 |
| 함수 수정 전 | 장소 수 지침 4곳 |
| 여유롭게 선택 후 함수 수정 | 장소 수 지침 최대 2곳 |

**AI 답변 예시:** ‘부산역에서 대중교통으로 이동할 두 곳을 묶고 중간에 휴식 시간을 두겠습니다. 교통편과 운영 시간은 출발 전에 확인하세요.’ 답변 표현은 매번 달라질 수 있습니다. 프로필의 이동 수단·속도·형식이 반영되는지 확인하고, 최신 시간·요금을 확인 없이 확정한 답은 그대로 여행 계획에 사용하지 않습니다.

## 4. 복습 과제

방문 장소 수를 정하는 함수에서 여유로운 여행은 2곳, 다른 스타일은 3곳으로 정책을 정합니다. 같은 여행 질문을 두 스타일로 보내고, 어떤 조건이 어떤 지침을 선택하는지 한 문장으로 설명합니다.

프로필 선택값을 바꾼 뒤 적용하지 않은 화면과 적용한 화면을 비교합니다. 대화가 초기화되는 시점과 프로필이 유지되는 시점을 각각 기록합니다. 다음 차시는 제공되는 파일에서 바로 시작할 수 있습니다.
