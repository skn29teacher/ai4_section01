# 오늘 수업 안내 — 나에게 맞는 여행 챗봇 공개하기

## 오늘 만들 결과물

Day20에서 만들었던 여행 챗봇에 여행 스타일과 이동 수단을 선택하는 화면을 더합니다. 답변 아래에서 도움 여부와 개선할 이유를 남기고, 동의한 평가를 Supabase에 보관합니다. 마지막에는 Streamlit Community Cloud에서 접속 가능한 개인 챗봇 주소를 만듭니다.

예를 들어 ‘부산에서 반나절 여행 일정을 제안해 주세요’라고 질문합니다. 대중교통을 선택한 경우 자동차 중심 동선을 피하도록 요청하고, 답변이 복잡하면 ‘너무 김’ 같은 이유를 남겨 다음 개선에 활용합니다. 운영 시간·가격·예약 가능 여부처럼 실제 확인이 필요한 정보는 여행 전에 확인합니다.

## 오늘의 진행 순서

| 차시 | 추가할 내용 | 마지막에 볼 결과 |
| --- | --- | --- |
| 1 | 여행 프로필과 응답 지침 | 선택한 조건이 보이는 챗봇 |
| 2 | 답변 번호와 피드백 | 서로 다른 답변에 연결된 평가 |
| 3 | 동의와 최소 수집 | 질문·답변 전문이 없는 평가 파일 |
| 4 | Supabase 저장 | DB에 남은 피드백 한 행 |
| 5 | 실패한 저장 재시도 | 중복 행 없이 저장된 평가 |
| 6 | 호출 제한과 공개 설정 | 제한 이유가 보이는 서비스 |
| 7 | GitHub와 Community Cloud 배포 | 휴대전화에서도 열리는 주소 |
| 8 | 평가 집계와 버전 개선 | 개선한 답변과 새 버전 표시 |

스트리밍과 성공한 대화 기록은 준비된 기반으로 사용합니다. 오늘은 스트리밍을 처음부터 다시 구현하는 대신, 답변을 누구의 조건에 맞추고 어떻게 개선할지 다룹니다.

## 시작 전 확인

기존 Python 실습 환경, Groq API 키, GitHub 계정을 준비합니다. 4차시부터 본인의 Supabase 프로젝트와 DB 연결 정보가 필요합니다. 7차시에서 Streamlit Community Cloud에 로그인하고 GitHub 저장소를 연결합니다. 연결 값은 본인의 `.env`와 클라우드 Secrets에만 넣습니다.

압축을 `C:\AI4\KDT_Personal_Travel`에 풀고 [1차시 교안](lesson01/README.md)의 명령을 실행합니다. 이전 Day20 파일을 덮어쓰지 않습니다. FastAPI나 Redis를 로컬에서 별도로 실행할 필요는 없습니다. 앱의 서버가 Groq와 Supabase에 직접 연결합니다.

## 완료 확인

본인 서비스 주소를 휴대전화에서 열고 여행 스타일과 이동 수단을 선택합니다. 여행 질문에 답변이 나온 뒤, 피드백 수집에 동의하고 평가를 전송합니다. Supabase SQL Editor에서 평가가 저장됐는지 확인합니다. 앱을 재시작한 뒤에도 DB의 평가는 남습니다.

여행 프로필과 대화는 현재 브라우저 연결에만 보관합니다. 새 연결에서 이전 대화가 복원되는 회원 서비스와는 보관 범위가 다릅니다. 공개 화면은 다른 방문자의 피드백 목록을 보여 주지 않습니다.

Community Cloud의 무료 호스팅과 Groq·Supabase의 무료 사용 범위는 각각 관리됩니다. 계정의 사용량과 한도를 확인하며 실습합니다. 다음 단원에서는 오늘 남긴 평가 데이터와 버전 정보를 에이전트 응답 품질을 점검하는 자료로 이어 사용합니다.
