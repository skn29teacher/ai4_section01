# 3차시. 동의한 최소 로그만 보관하고 내보내기

## 1. 학습목표

[오늘 수업 안내](../TODAY_GUIDE.md)를 읽습니다. 답변별 평가에 수집 동의와 생성 조건을 연결합니다. 단순히 평가 버튼을 더하는 것에서 나아가, 필요한 정보만 남기는 기준을 만듭니다.

- 동의 전후의 피드백 저장 결과를 구분할 수 있습니다.
- 답변 생성 당시의 여행 프로필과 버전을 로그에서 찾을 수 있습니다.
- 내보내기 함수 한 곳에서 프로필을 제외하고 비교할 수 있습니다.

## 2. 중요 알고리즘 및 코드를 읽을 때 반드시 알아야 할 내용

프로필을 바꾼 뒤 예전 평가를 보면 어떤 조건에서 만든 답변인지 알기 어렵습니다. 반대로 품질을 분석한다는 이유로 질문과 답변을 전부 모으면 필요 이상의 정보를 보관하게 됩니다.

답변이 성공할 때 선택한 프로필과 버전을 복사해 함께 붙입니다. **스냅샷**은 그 순간의 값을 따로 보관한 것입니다. `deepcopy()`를 사용하면 이후 현재 프로필을 바꿔도 과거 답변의 선택값을 따라 바꾸지 않습니다.

피드백을 저장할 때 `make_record()`는 답변 번호·평가·이유·프로필·모델·버전·제출 시간을 만듭니다. 질문과 답변 전문은 이 기록에 넣지 않습니다. 화면에 보이는 대화와 저장할 평가 기록은 서로 다른 자료입니다.

```python
def export_record(record):
    return dict(record)
```

현재 함수는 평가 기록을 복사해 내보냅니다. 내보내기만 더 줄이고 싶다면 이 함수에서 항목을 제외합니다. 원본 피드백을 직접 지우는 대신 별도의 복사본을 만들기 때문에 앱의 평가 기록에는 영향을 주지 않습니다.

**JSONL**은 한 줄마다 JSON 기록 하나를 담는 형식입니다. `json.dumps()`는 딕셔너리를 JSON 문자열로 바꾸고, `"\n".join(...)`은 평가마다 줄을 나눠 연결합니다. 실제 환경설정은 계속 `.env`를 사용합니다.

참고: [Python JSON](https://docs.python.org/3/library/json.html), [Streamlit 세션 상태](https://docs.streamlit.io/develop/api-reference/caching-and-state/st.session_state).

## 3. 코드 제공

실행 파일은 [main.py](main.py)입니다. Windows CMD에서 해당 차시를 실행합니다. `.env`가 있으면 복사하지 않습니다.

```bat
cd /d C:\AI4\KDT_Personal_Travel\lesson03
python -m pip install -r requirements.txt
copy .env.example .env
notepad .env
python -m streamlit run main.py
```

`GROQ_API_KEY`를 입력해 저장하고 Local URL을 엽니다. 종료는 Ctrl+C입니다. 이번 차시는 동의한 평가를 현재 세션에 보관하고 다운로드하며 원격 DB에는 전송하지 않습니다.

### 1단계. 동의와 수집 항목 확인

‘전주에서 먹거리 중심으로 하루 일정을 제안해 주세요’라고 질문합니다. 답변 아래에서 평가를 선택하고 동의하지 않은 채 **피드백 저장**을 누릅니다. `저장하려면 피드백 저장에 동의하세요.`가 보이는지 확인합니다.

수집 항목 안내를 읽고 **이 피드백의 저장에 동의합니다.**를 선택한 뒤 저장합니다. **이 연결에서 저장한 피드백**을 펼치고 **내 피드백 JSONL 다운로드**를 누릅니다. 파일을 메모장으로 열어 `profile`, `model`, `app_version`, `prompt_version`을 찾습니다. `created_at`은 이 평가를 제출한 시각이며 시간과 ID는 실행마다 다릅니다.

### 2단계. 내보내기에서 프로필만 제외

현재 `export_record()`는 `return dict(record)`로 모든 평가 항목을 내보냅니다. 함수 하나만 아래처럼 교체합니다.

```python
def export_record(record):
    exported = dict(record)
    exported.pop("profile", None)
    return exported
```

`pop("profile", None)`은 `profile` 항목이 있으면 꺼내 제거하고, 없어도 오류 대신 `None`을 반환합니다. 여기서는 반환값보다 항목을 제외하는 동작을 사용합니다. 평가 원본은 그대로 두고 다운로드 자료의 범위만 줄입니다.

### 3단계. 같은 평가를 다시 내려받기

파일을 저장하고 다운로드를 다시 누릅니다. 다시 실행하면서 세션이 초기화됐다면 같은 질문을 보내 동의 후 평가를 저장합니다. 새 JSONL에는 `profile`이 없고 평가·이유·버전·답변 번호는 남아 있는지 확인합니다.

프로필을 변경해 새 대화를 시작하더라도 이미 보관된 평가의 프로필 값은 평가 생성 조건으로 남습니다. **새 대화**는 대화를 비우는 버튼이며 현재 연결의 피드백 기록을 모두 삭제하는 버튼이 아닙니다. 동의 체크를 나중에 해제하는 것만으로 이미 저장한 기록이 삭제되지는 않습니다.

### 예상 결과

| 조작 | 결과 |
| --- | --- |
| 동의 없이 저장 | 동의 안내, 새 평가 기록 없음 |
| 동의 후 첫 저장 | `피드백 저장 완료`, 현재 연결의 피드백 1개 |
| 같은 답변 재평가 | 같은 ID의 최신 평가, 개수는 1개 |
| 수정 전 다운로드 | 선택한 `profile` 포함 |
| 수정 후 다운로드 | `profile` 제외, 평가·이유·버전 유지 |
| 질문·답변 전문 검색 | 평가 JSONL에 없음 |

## 4. 복습 과제

내보내기 함수에서 `model` 항목도 제외합니다. 다운로드한 파일에서 평가·이유·프롬프트 버전은 남아 있고 `profile`과 `model`은 없는지 확인합니다.

앞으로 수집하고 싶은 항목 하나를 정하고 ‘어떤 개선 판단에 필요한가’를 한 문장으로 적습니다. 필요성을 설명할 수 없는 항목은 추가하지 않습니다. 다음 차시는 제공되는 원본 내보내기 정책에서 시작합니다.
