# 6차시. 공개 서비스의 입력과 호출을 제한하기

## 1. 학습목표

[오늘 수업 안내](../TODAY_GUIDE.md)를 읽습니다. 여러 사람이 여는 서비스에서는 너무 긴 질문과 연속 요청에도 사용할 수 있는 안내가 필요합니다. 모델 호출 전에 거절할 입력과 잠시 뒤 다시 시도할 요청을 구분합니다.

- 길이 초과 질문을 API 호출 전에 거절하고 다시 입력할 수 있습니다.
- 질문 재시도와 피드백 재시도를 구분할 수 있습니다.
- 링크를 여러 개 붙인 입력을 한 함수에서 제한할 수 있습니다.

## 2. 중요 알고리즘 및 코드를 읽을 때 반드시 알아야 할 내용

무료 배포 주소를 만들었다고 모델을 제한 없이 호출할 수 있는 것은 아닙니다. 긴 입력이나 연속 제출이 반복되면 계정 한도를 빠르게 쓸 수 있습니다. 앱은 요청 전에 간단한 기준을 확인하고, 거절 이유를 보여 주어 입력을 고칠 수 있게 합니다.

`question_error(question)`은 질문 내용을 검사합니다. 오류 문장을 돌려주면 모델을 호출하지 않고 안내를 보여 줍니다. `None`은 이 검사에서 거절할 이유가 없다는 뜻입니다. 현재 함수는 `len(question) > MAX_QUESTION_CHARS`로 길이를 검사합니다.

| 기준 | 시작 값 | 거절 뒤 행동 |
| --- | ---: | --- |
| 질문 길이 | 1,000자 이내 | 내용을 줄여 다시 입력 |
| 요청 간격 | 최소 3초 | 기다린 뒤 질문 재시도 |
| 현재 연결의 시도 횟수 | 최대 30회 | 질문을 취소하고 이용 종료 |

시도 횟수에는 실패한 모델 요청도 들어갑니다. 새 대화 버튼으로 대화를 비워도 횟수는 그대로입니다. 새 연결에서는 초기화되므로 이 장치만으로 계정 전체 비용이나 오용을 막을 수는 없습니다. 공급자의 계정 한도와 사용량을 함께 확인합니다.

로컬의 `.env`와 클라우드 Secrets는 같은 이름의 설정을 전달합니다. `load_dotenv(".env", override=False, interpolate=False)`는 이미 있는 서버 환경변수를 파일 값으로 덮어쓰지 않습니다. 클라우드 키는 앱 화면이나 Git이 아닌 Secrets에 넣습니다.

참고: [Groq 호출 한도](https://console.groq.com/docs/rate-limits), [Streamlit Secrets](https://docs.streamlit.io/develop/concepts/connections/secrets-management).

## 3. 코드 제공

실행 파일은 [main.py](main.py)입니다. Windows CMD에서 다음 순서로 실행합니다. `.env`가 이미 있으면 복사를 생략합니다.

```bat
cd /d C:\AI4\KDT_Personal_Travel\lesson06
python -m pip install -r requirements.txt
copy .env.example .env
notepad .env
python -m streamlit run main.py
```

`GROQ_API_KEY`와 `DATABASE_URL`을 입력하고 `SHOW_DEMO_TOOLS=false`를 유지합니다. 처음 연결하는 DB라면 [서비스 연결 안내](../BACKEND_GUIDE.md)에 따라 로컬에서만 도구를 잠시 켜 테이블을 준비한 뒤 다시 `false`로 바꾸고 재실행합니다. Local URL을 열고 종료는 Ctrl+C입니다.

### 1단계. 길이 제한과 요청 안내 확인

‘여수에서 하루 여행할 일정을 제안해 주세요’라고 보내 정상 답변을 받습니다. 화면의 `질문 1000자 · 요청 간격 3초 · 연결당 최대 30회` 안내를 확인합니다.

길이 초과를 확인하려면 다른 CMD에서 아래 명령을 실행합니다. `-c`는 따옴표 안의 짧은 Python 코드를 바로 실행합니다. 출력된 글자를 복사해 질문창에 붙여 넣습니다.

```bat
python -c "print('가' * 1001)"
```

`질문은 1000자 이내로 입력하세요.`가 보이고 새 미완성 질문이 생기지 않아야 합니다. 짧은 여행 질문으로 바로 수정해 제출할 수 있어야 합니다.

### 2단계. 링크 개수 정책 한 곳 추가

현재 `question_error()`는 길이만 검사하므로 짧은 링크 여러 개도 모델에 전달할 수 있습니다. 이 챗봇은 URL을 열어 문서를 읽는 기능이 없습니다. `question_error()` 함수 하나를 다음으로 교체합니다.

```python
def question_error(question):
    if len(question) > MAX_QUESTION_CHARS:
        return f"질문은 {MAX_QUESTION_CHARS}자 이내로 입력하세요."
    if question.count("http://") + question.count("https://") > 2:
        return "링크는 2개 이하로 줄여 주세요. 이 챗봇은 링크를 열어 읽지 않습니다."
    return None
```

`count()`는 해당 문자열이 나온 횟수를 셉니다. 두 종류의 시작 문구 수를 더해 3개 이상이면 거절합니다. 전체 URL을 정밀하게 분석하는 기능이 아니라 이번 입력 정책의 간단한 기준입니다.

### 3단계. 같은 입력으로 거절과 수정 비교

수정 전에는 다음 입력이 길이 검사를 통과합니다. 수정 후 다시 보내 즉시 안내가 나오는지 봅니다.

> 이 링크들을 읽고 비교해 줘 https://example.com/a https://example.com/b https://example.com/c

링크를 하나로 줄이고 실제 여행 조건을 글로 적어 다시 제출합니다. ‘링크가 적으면 실제 페이지를 읽는다’는 뜻은 아닙니다. 일정에 필요한 지역·기간·이동 조건을 질문에 직접 씁니다.

3초 안에 다음 요청이 도착하면 `잠시 기다린 뒤 질문을 재시도하세요.`가 보입니다. 미완성 질문은 보관되므로 3초 뒤 **질문 재시도**로 계속하거나 **질문 취소**로 입력을 다시 작성합니다. 모델 답변이 오래 걸리면 이미 3초가 지나 이 분기가 나타나지 않을 수 있습니다.

현재 연결의 시도가 30회가 되면 `이 연결의 요청 한도에 도달했습니다. 질문을 취소하고 나중에 이용하세요.`가 보입니다. 같은 연결에서 기다려도 횟수 제한은 풀리지 않습니다. **질문 취소**로 입력 상태를 정리하고 종료합니다. 이 한도를 관찰하려고 의미 없는 질문 30회를 반복 호출할 필요는 없습니다.

### 예상 결과

| 입력·조작 | 결과 |
| --- | --- |
| 1,001자 질문 | `질문은 1000자 이내로 입력하세요.`, API 미호출 |
| 짧은 여행 질문 | 요청 가능, 완성 뒤 대화 이력 추가 |
| 수정 전, 링크 3개 | 길이 검사 통과 |
| 수정 후, 링크 3개 | 링크 개수 안내, API 미호출 |
| 요청 간격 부족 | 대기 후 질문 재시도 또는 취소 가능 |
| 연결 시도 한도 도달 | 대기만으로 복구되지 않음, 취소 가능 |

AI의 여행 제안은 매번 달라질 수 있습니다. 이 차시는 답변 내용이 아니라 모델 호출 전의 거절과 복구 행동을 비교합니다. SDK 오류의 원문이나 연결 비밀값은 화면에 출력하지 않습니다.

## 4. 복습 과제

공개 안내에서 ‘현재 연결의 제한’과 ‘Groq 계정 전체의 한도’를 구분한 짧은 이용 문구를 작성합니다. 새로운 연결로 앱 정책을 우회할 수 있다는 한계를 포함합니다.
